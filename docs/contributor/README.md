# Contributor Docs

This section is for people changing Meridian itself rather than just using it.
Start here after you already have one CLI, UI, or SDK workflow running.

## Start Here

- [Starting Points](./starting-points.md): contributor map for core, UI, CLI,
  SDK, rendering, and tests
- [Testing Guide](./testing.md): focused validation commands by subsystem
- [Releasing](./releasing.md): shared versioning, tag flow, and GitHub release process

## Practical Order

1. Use [Getting Started](../getting-started.md) first if you have not already
   built the workspace and run one real workflow.
2. Use [Starting Points](./starting-points.md) to find the right code entrypoint
   before reading broad module trees.
3. Use [Testing Guide](./testing.md) to run the smallest useful regression
   commands for the surface you changed.
